# bathy v0.1 — Implementation Plan Overview

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement these plans task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build an open-source, agent-native network discovery engine that turns authorized network questions into bounded scan plans, executes them, and returns structured, evidence-backed findings over MCP.

**Architecture:** A Rust workspace with a hard separation between three layers: (1) a *contract layer* of pure types that generate JSON Schema, (2) a *conventional scanning engine* that never has an LLM on its packet path, and (3) *interface adapters* (CLI, MCP) that are thin translators over the engine. Evidence is content-addressed and immutable; interpretation of evidence into findings is a pure function, which makes results replayable and regression-testable without a network.

**Tech Stack:** Rust 1.85+ (edition 2024), Tokio, serde + schemars, rmcp (MCP), rusqlite, rustls, hickory-dns, etherparse + socket2, wasmtime (deferred to v0.2), blake3, tracing, proptest, cargo-fuzz, criterion.

## Global Constraints

Every task's requirements implicitly include this section.

- **Rust 1.85 minimum**, edition 2024. Pinned in `rust-toolchain.toml`.
- **License: Apache-2.0 OR MIT** (dual, Rust ecosystem convention). Every crate declares it.
- **Clean-room.** Do not read, copy, translate, or derive from Nmap source, `nmap-service-probes`, `nmap-os-db`, or any Nmap probe/fingerprint data. All probe and fingerprint data in this project must be independently authored and licensed. This is a legal requirement, not a style preference.
- **`#![forbid(unsafe_code)]`** in every crate except `bathy-packetd`, which may use `unsafe` only for raw socket syscalls and must document every block.
- **No LLM on the packet path.** No crate below `bathy-mcp` may take a dependency on any model/inference client. Enforced by an `xtask` dependency check.
- **No panics in parsing paths.** Any function that consumes bytes from the network returns `Result`. `unwrap()`/`expect()`/indexing-slice panics are denied by lint in `bathy-probe` and `bathy-interpret`.
- **Determinism claim is scoped.** We claim *deterministic planning* (same request + same scope manifest → same `plan_hash`) and *reproducible interpretation* (same evidence bytes + same engine version → same findings). We do **not** claim reproducible observations; the network is not deterministic. No doc, README, or code comment may make the unscoped claim. `[phrase-rule]`

  **Sentinel convention.** The forbidden phrase is enforced by grep, so the rule's own statement would otherwise trip its own check — the first CI run would fail on `ci.yml` itself. Any line that legitimately names a forbidden phrase (to define, test, or enforce the rule) must carry the marker `[phrase-rule]`, and every check excludes marked lines. A new forbidden phrase is added in exactly two places: the checker's list, and here.
- **Deny-by-default scope.** No packet is ever emitted to an address that is not inside an active, unexpired scope manifest's allow set and outside its deny set.
- **Canonical hashing.** All hashes (`plan_hash`, evidence digests) use BLAKE3, rendered as `blake3:<64 lowercase hex>`. Structured values are canonicalized with RFC 8785 (JSON Canonicalization Scheme) before hashing.
- **IDs are ULIDs** with a type prefix: `scan_01K…`, `evt_01K…`, `scope_01K…`. Generated only through a `Clock` implementation; never by calling `Ulid::new()` at a use site.
- **All timestamps are RFC 3339 UTC with milliseconds.** Clock access is injected via the `Clock` trait, never `SystemTime::now()` directly, so tests are deterministic. `Clock` lives in `bathy-types` — it is a pure trait with no I/O, and putting it in `bathy-store` would force `bathy-evidence` to depend on a higher layer.
- **Linux first.** macOS is best-effort; Windows is explicitly out of scope for v0.1 (Npcap's license is incompatible with our goals — see `docs/platform-support.md`, Milestone 7).
- **Every finding carries evidence.** A `Finding` cannot be constructed without at least one `EvidenceRef`. Enforce in the type system, not by convention.

## Milestones

Each milestone is a separate plan file and produces working, testable software on its own.

| # | Plan | Produces | Depends on |
|---|---|---|---|
| M1 | `…-m1-contracts.md` | Workspace, CI, all core types, JSON Schema export, scope/policy/budget engine. `bathy-scope` can accept or deny a target with a reason. | — |
| M2 | `…-m2-evidence-state.md` | Content-addressed evidence store, append-only JSONL event log, SQLite task store with idempotency and resumable cursors. | M1 |
| M3 | `…-m3-planner-engine.md` | Deterministic planner with `plan_hash`, budget-governed scheduler, TCP connect scanning, ICMP/TCP host discovery. **A working scanner.** | M1, M2 |
| M4 | `…-m4-probes-interpret.md` | Probe framework, HTTP/TLS/SSH/DNS/SMTP/Postgres/MySQL/Redis probes, pure replayable interpretation layer. **Service identification with evidence.** | M1, M2, M3 |
| M5 | `…-m5-interfaces.md` | `bathy` CLI, MCP server with 11 tools, `result.query`, `result.diff`. **The agent-facing product.** | M1–M4 |
| M6 | `…-m6-packetd.md` | Privileged SYN scanning in a separate capability-dropping process. | M3 |
| M7 | `…-m7-verification.md` | Docker integration lab, fuzz targets, criterion benchmarks, design paper, README, SECURITY.md, publication checklist. | M1–M6 |

**Recommended execution order:** M1 → M2 → M3 → M4 → M5 → M7 → M6. M6 is deliberately last-but-one: SYN scanning is an optimization, and shipping the interface and verification story first is what de-risks the project. M7's lab is needed to properly test M6.

## Gap Register — spec items deliberately deferred

Recorded here because an audit that does not know what was intentionally left out will report it as a failure. Each line states what the source design document asked for, what these plans deliver, and why.

| Spec item | Status | Rationale |
|---|---|---|
| **ICMP/TCP host discovery** | TCP in M3, ICMP in M6 Task 5 | Unprivileged ICMP is not possible; it needs the same raw-socket capability as SYN scanning, so it belongs with `packetd`. Both halves ship in v0.1. |
| **"Signed/approved target manifests"** | Approval and expiry in v0.1; cryptographic signing **deferred to v0.2** | Signing is only meaningful with a key-distribution and revocation story, and shipping a signature field nobody verifies is worse than shipping none. v0.1 manifests are files with an expiry, validated on every scan. `ScopeManifest` reserves an optional `signature` field so adding verification is not a breaking change. |
| **A2A Agent Card at `/.well-known/agent-card.json`** | **Deferred to v0.2** | The source document itself calls A2A optional and MCP the lower-level interface that coding and automation harnesses use. Shipping one protocol well beats shipping two adequately. |
| **WASM/WASI plugin runtime** | **Deferred to v0.2** | Not in the source document's own v0.1 list. The eight built-in probes are compiled in; the `Probe` trait is the seam a WASM host slots behind later. |
| **OS fingerprinting, UDP breadth, traceroute, evasion modes** | **Out of scope**, per the source document | Explicitly deferred by the design document. Evasion is additionally a permanent non-goal — see M7 Task 5. |
| **IPv6 scanning** | **Out of scope for v0.1**, gap noted | The source document does not mention IPv6 at all, which is a notable omission for a greenfield 2026 scanner. Types are `IpAddr` throughout and `bathy-scope` already refuses IPv6 reserved ranges, so v0.2 is additive rather than a rewrite. Must be listed in the README's limitations. |
| **Measurement-derived port prevalence ranking** | **Deferred to v0.2** | v0.1 ports are an IANA-derived heuristic. This and fingerprint breadth are the two largest gaps between bathy and a mature scanner, and M3 Task 2 and M7 Task 4 both require saying so plainly rather than implying parity. |
| **`Clock` creation** | Trait and implementations (`SystemClock`, `FixedClock`) created in **M2 Task 1** | `bathy-types` is `Clock`'s permanent home (Global Constraint; a pure trait with no I/O, so `bathy-evidence` — which needs it and sits below `bathy-store` in the layer order — can depend on it). Listed under `bathy-types` in the File Structure above because that is where the file lives, not because M1 creates it: no M1 task constructs `Clock`, and M1's own ULID/timestamp fields are supplied externally in tests. M2 Task 1 is the task that actually creates it, and specifies its tests. |

## Audit Procedure (step 3 of the user's workflow)

Every task in every milestone plan carries numbered acceptance criteria of the form `AC-<milestone>.<n>`. These are the audit surface.

To audit an implementation against these plans:

1. Collect every `AC-*` line across all seven plans into a matrix.
2. For each, record: **MET** (with the file:line and the passing test name that proves it), **PARTIAL** (with what is missing), **UNMET**, or **DEVIATED** (implementation differs from plan — record whether the deviation is an improvement, a regression, or neutral, and why).
3. An AC may only be marked MET if there is an automated test that fails when the behavior is removed. "The code looks right" is not evidence.
4. Separately verify the **Global Constraints** above, which are not attached to any single AC. In particular: run `xtask check-deps`, `cargo deny check`, confirm no `unsafe` outside `bathy-packetd`, and grep the whole repo for the unscoped determinism phrase, excluding `[phrase-rule]`-marked lines.
5. Report as a table, most severe gaps first. Do not fix during the audit — audit and remediation are separate passes so the audit stays honest.

## Pre-Publication Gates (step 4 of the user's workflow)

These must be cleared **before** the repo is pushed public. They are checked in M7 but listed here because they gate the whole project.

- [ ] **Name availability confirmed** — `bathy` on crates.io, GitHub org, and domain. There is a plausible existing `bathy` crate in the DTrace/USDT space; if taken, the fallback order is `fathom` → `assay` → `reckon`. Renaming is a workspace-wide `sed` plus a `Cargo.toml` sweep; do it before first publish, never after.
- [ ] **No research artifacts in the repo.** `~/Nmapharness/nmap fyodor - Google Search.html` and its `_files/` directory contain the owner's Google account email, an inferred physical location, and a live Google XSRF token. The repo root is `~/Nmapharness/bathy/`, and these files must never be added. Verify with `git ls-files | grep -i -E 'google|fyodor'` returning empty.
- [ ] **Clean-room attestation** in `docs/design-paper.md`, stating no Nmap source or data was consulted.
- [ ] **`SECURITY.md` present** with a vulnerability disclosure path and an explicit authorized-use statement.
- [ ] **README does not position the project against a person.** Positioning is technical and comparative only.
- [ ] `cargo deny check` clean, `cargo test --workspace` green, lab integration suite green.
